# 小地球现状与基础打磨评估

检查日期：2026-10-15（北京时间）。本轮目标是处理基础质感与可用性。

## 当前完成到哪里

这是可交互的三维视觉基础。Babylon.js 9.30.0 已提供网格、PBR 材质、HDR 环境、阴影和相机；Blender 提供可编辑工程与 GLB。已有旋转、滚轮和双指缩放、键盘输入、三种光照预设及五项参数。

v0.4 的导出网格包含约 11.9 万三角形，陆地按球面面积估算约 47.9%，最高地表半径约 1.017。基础几何已具备继续打磨的条件。自由造景、生态模拟、存档、精细像素美术和摄像头手势尚未实现，不能据此称为完整游戏。

## 基础粗糙的具体原因与处理

| 问题 | 代码证据与影响 | v0.4.1 处理 |
| --- | --- | --- |
| 竖屏球体裁切 | 相机固定竖向 FOV；393×852 下横向投影超出画面 | 根据短边选择 FOV，留出操作区；调整尺寸不改变视角和缩放 |
| 地表大块颜色缺乏细节 | 网格顶点色承担全部地表色彩，靠近后显得单薄 | 在 PBR 中增加低对比、连续三维色彩细节，远处自动衰减；保留海岸颜色 |
| 细波与反光偏硬 | 四组高频正弦波直接进入法线，轮廓和远处缺少采样过滤；粗糙度 0.20 | 按屏幕导数衰减不足一个像素的波纹，降低波幅，粗糙度调至 0.26 |
| 页面反馈不足 | 等待引擎或模型时主要依赖左上角小字，缺少直接重试 | 独立轻量启动脚本、加载和慢加载提示、失败重试、基础版入口 |
| 控件偏小 | 常用按钮 36px，多处文字 10–11px，面板关闭按钮 24px | 常用按钮和关闭按钮 44px，增加面板字号与滑块操作区 |
| 缩放与触控反馈不足 | 没有比例或边界状态，固定每像素旋转速度，捕获丢失后清理不完整 | 比例显示、边界禁用、按短边调整拖动灵敏度、统一指针释放与焦点处理 |

无需为了这些问题更换引擎或继续增加网格。沿用 [Babylon.js](https://github.com/BabylonJS/Babylon.js) 的相机与材质插件能力即可，避免引入第二套渲染逻辑。当前版本锁定与本地托管方式继续保留。

## 实际验证与剩余边界

`npm run build`、`npm run check` 完成构建和实际 GLB 导入，验证网格、接缝、海陆比例、材质插件、光照、波纹参数、相机边界和复位。投影检查覆盖六种横竖屏尺寸，同时复现旧版竖屏裁切，确认修复后球体完整且保持圆形。

`python scripts/check-shaders.py` 使用实际准备的 PBR 源码，在明确适配的 EGL / desktop OpenGL 上编译、链接陆海程序。JavaScript 语法与 Git 空白检查也通过。结果保留在 `docs/previews/polish-v0.4.1/`，旧验证记录不覆盖。

当前没有指定的浏览器控制技能。上述检查不等于浏览器 WebGL 画面、CSS 响应式、实际点击、触屏手感或设备性能已经通过。地表细节与水面过滤的最终观感仍需要在实际网页确认。

## 后续顺序

1. 先在实际网页确认默认光感、海岸、海面反射，以及手机横竖屏、缩放和连续拖动的表现，按反馈校准本轮参数。
2. 再制作一块精细像素地表的近景样片，检验像素尺度、球体圆润程度、接缝与远近采样。通过后才扩展整球美术。
3. 然后逐层加入河流、少量植被与可放置物件，并形成最小可玩的造景和存档流程。
4. 摄像头手势映射到已有稳定操作；之后再扩展生态。手势需真人和真实摄像头验收。

每一步都应有可查看的成果和对应验收，避免在基础观感未稳定时叠加世界内容。
